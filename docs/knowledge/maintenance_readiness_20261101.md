# 真实远程快照的本地诊断与修补（2026-11-01）

本轮没有推送或部署。远程源库通过mode=ro、query_only=ON和固定读事务读取，只向/tmp下单独快照写入；复制完成即释放读事务。没有对源库执行DML、清理、VACUUM、结构变更，也没有重启远程服务。复制、压缩过程中会产生只读I/O，不能表述成远程零负载。远程临时文件在本地SHA256校验成功后逐个核验删除。

## 两项修补

1. 清理任务不再在线程池排队、等待checkpoint期间预先暂停游戏。线程先做非阻塞预检查并释放锁，然后请主循环发布屏障并确认；交接时不持锁，防止同步登录等锁形成环路。确认后再次非阻塞取锁，忙则不改游标、稍后重试。保留独立导入标记、写入前同步保护和取消等待。真实库上模拟checkpoint持锁1秒，旧实现门控等待0.941秒；修补后门控不等待。
2. 过期结算生命周期查询原来选玩家索引，每个结算重复扫描该玩家所有战斗记录。派生查询用LIMIT -1阻止扁平化，先按现有UUID索引寻找全部匹配，再判归属和时间；不能LIMIT 1，因为历史UUID可能重复。真实快照同一组496条结果、摘要一致，查询23.3911秒降至0.0257秒。该改动同时作用于导出过滤、导入后清理和后台清理，不新增索引或改变保留规则。

最初本地交接实现持锁等待主循环确认，真实库50登录暴露环路；该中间版本未推送，已用确定性测试复现后修正。不能将早期失败压测记录当作最终代码表现，原失败日志保留。

## 业务验证与限度

最终组合79个不同相关用例通过，含取消、线程池排队、主循环事务、交接不持锁、预检查后抢锁、重复UUID/账号归属/时间边界、清理幂等与回滚、完整存档往返、HTTP和慢速下载。

真实副本中三个较大账号档案44.86MB、29.77MB、29.61MB均可导出，102张表结构解析成功、ZIP CRC通过；其中最大账号同账号导入通过，最终quick_check=ok。测试进程组合了导出、解析及再导入，峰值约1.1GB，不能据此声称线上单次导出一定使用这么多内存。

合成库50客户端200场战斗与重放、并发导入通过，不代表真实库已达到50人SLO。真实库压测记录在runtime/retention_ready_20261101，最终常规玩法和超大存档场景应分开报告。包含超大存档的最终尝试已通过50人登录，但后续出现8.266秒停顿和连接重置，未得到完整通过结果；该停顿尚不能归因到一条SQL，不能宣称卡顿已全部解决。测试工具关闭连接时的异常可能掩盖原始错误，后续本地工具已改为记录原请求失败并单独处理关闭异常。

大档完整导出、解析、备份和覆盖写入仍可能耗时，真实远程硬件只有有限内存/磁盘性能；不因一个查询变快就承诺整体性能。本轮既没有删减必要业务账簿，也没有降低存档校验或原子性。
