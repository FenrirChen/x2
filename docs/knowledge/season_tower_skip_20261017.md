# 赛季塔按通关时间跳层（2026-10-17）

用户规则：仅挑战成功时增加可挑战层数。以本次实际挑战层 x 为起点，而不是在当前最高解锁层上重复累加。

| 本次结算用时 | 跳过层数 | 最高可解锁层 |
| --- | --- | --- |
| 0 < t < 300 秒 | 2 | x+3 |
| 300 < t < 600 秒 | 1 | x+2 |
| t=300 秒，或 t>=600 秒 | 0 | x+1 |

5 分钟整和 10 分钟整按用户原文的严格区间不跳层。客户端上报用时 0 时，复用 BattleService 原有的服务端入场耗时回退后再判断；不把缺失的 0 秒当作极速通关。

## 进度与奖励

- `season_state.state_json.unlocked_layer` 保存最高可挑战层。查询的 maxSeasonId 和真实入场、绑定 run 的校验共用此值。
- `max_layer` 继续表示最高实际通关层，maxPassId、成就和任务仍使用真实通关记录，不将被跳过的层冒充为已挑战成功。
- `season_runs` 不为跳过的层插入成功记录；既有首通奖励按此账本判断，所以后来仍可回打被跳过的层领取其自身奖励，不会提前发放或消耗其奖励资格。
- 只消耗实际入场层的挑战券；跳层本身不额外扣票，也不自动发跳过层的奖励。
- 已结束 run 的重复结算不再次推进。重打低层的目标仍为那个低层的 x+1/2/3，与已有前沿取较大值，不能无限叠加。
- 失败不跳层、不推进，保留原有失败退票处理。最高解锁层封顶现有最高配置（当前 100 层）。

## 兼容性

旧存档没有 unlocked_layer 时，按原 max_layer+1 初始化，不回退原进度，也不追溯过去的快速通关额外开放新层。新字段随已有完整赛季存档导出/导入，不新增数据库表。

同一赛季内的周刷新和重启保留解锁前沿；不同赛季期次使用各自 season_state，初始开放第 1 层。本轮不修改安装包、测试存档进度或远程部署。
