# 存档操作并发修复（2026-10-17）

## 线上证据与边界

远程 main 为 08665ba。调查期间服务仍在运行、NRestarts=0，玩家断线对应 connection task failed: database is locked，而非已证实的进程退出。21:50、21:52、22:02、22:13 的存档请求附近出现 SQLITE_BUSY、连接异常；主线程曾处于 swap page 等待，IO 压力较高。不能把所有掉线都归因于进程停止。

远程一份导入前备份含 27019 个 ZIP 条目，展开约 97 MiB，其中 save.json 约 77 MiB。旧实现会全量构造导出对象、重复解析备份，并在导入写事务内扫描全服 UUID/ID，延长锁和内存压力。原始玩家日志、存档及服务器凭据不加入仓库。

## 实现

- 主库使用 WAL + synchronous=FULL，导出读快照与游戏写入可并行；不降低持久性等级。
- 所有应用写连接关闭自动 checkpoint，由游戏循环单一执行 PASSIVE checkpoint；HTTP、存档导入和注册管理写入通过进程文件锁与 checkpoint 互斥。旧 SQLite 存在 WAL reset 竞争问题，因此不能随意增加独立 checkpoint/写库程序。外部手工维护应先停服。参照 https://www.sqlite.org/wal.html 。
- 导入的解析和备份在写入屏障之外完成；短写事务期间游戏请求和后台业务异步等待，原有事务仍保持原子性。屏障内再次检查目标账号离线。
- 临时数据库忙返回协议允许的失败应答，避免直接关闭游戏连接；不自动重试变更请求。HTTP 返回 503 和 Retry-After。
- 存档导入/导出重任务限制为一个，超出返回繁忙，避免内存叠加。
- 启动时为存档表补齐 player_id/碰撞键索引；按待导入候选分批检查冲突，不再加载全服 ID 集合。注册状态查询改为只读。
- 导出 JSON 逐行写 ZIP，BLOB 临时落盘；导入复用解析行对象。备份校验使用 ZIP/hash 流式检查，不再构造另一份完整 ImportPlan。
- 备份先写临时文件并校验成功，再原子替换；失败保留旧备份。每账号一份备份、账号身份及一次性邮件防重复规则保留。大型 manifest 的备份归属扫描上限同步修正。
- 新增导入阶段耗时、导出耗时、数据库错误堆栈、主循环停顿及 RSS/swap 日志。
- 部署脚本处理 checkpoint 锁文件权限；默认健康等待增至 180 次，允许首次索引创建，支持 X2_HEALTH_ATTEMPTS 设置。
