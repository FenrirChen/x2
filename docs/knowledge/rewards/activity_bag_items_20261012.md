# 2026-10-12 活动背包物品使用审查

审查七个开放主题的商店、任务、奖池、关卡固定奖励、静态掉落根、年兽红包、答题、额外掉落及剧情奖励，并沿礼包内容追踪盒中盒。静态掉落根不能完整列举所有动态生成的掉落，所以同时审查整份可使用物品目录，避免漏掉古代礼包、迭代礼包、樱花信笺等物品。

## 审查结果

- 客户端 Item.Used 的218条关联与服务端全部一致，234组使用奖励包含固定、随机、自选和徽章盲盒。
- 在一次性临时数据库中，逐个实际发放1,351个非零候选并回滚，涉及货币、材料、礼包、神格、宝石、兽主、外观、徽章和碎片；未发现缺失物品、未实现发放目的地或缺少兽主星级证据。
- 7个零数量候选属于原版随机赠品空结果，保留该概率，不因抽空回滚以便免费重抽。随机三星礼包没有空候选。
- 随机使用按原版权重之和抽取，批量使用逐件抽取；自选按原版选取数量、下标和去重要求验证。
- 扣物品、发奖励、活动统计和结果回执在同一事务中；重复请求返回保存结果，失败回滚；神格重复转原版碎片和补偿票，兽主写独立实例及原版标注星级。
- 盒中盒以新礼包留在背包，下一次使用独立结算，不自动把所有层次拆完。

覆盖常见物品：迷你/精致/惊喜礼物盒、3★神格随机礼包、原石残片、影域礼包、新年红包、古代礼包、迭代礼包、樱花信笺、经验/因果卡以及各类兽主和自选宝箱。自动审查结果是服务端配置/发放路径证据，不是客户端UI手动验收。

## 本轮修复

1. 背包开启得到活动代币时，之前仅更新余额，未记录本期“获得代币”的任务和统计。现在按已有ActivityService.obtained统一通知，幂等且按当前活动期别隔离；不同货币不会完成错误活动的任务。
2. 新年红包等礼包可能包含体力。原先先加礼包再自然恢复，有时会截掉尚未结算的恢复量，或把礼包奖励裁到自然上限。现与因果卡一致，先结算旧余额的自然恢复，再发礼包体力，允许奖励超过自然恢复上限。
3. 查询活动任务时，按当前期成功使用回执和已提交发放账本补记历史遗漏的代币。只补统计，不再次发放物品；不能把上期使用回执带到下一轮。同一回执的实时统计和历史恢复使用同一个幂等键。

以上不改概率、奖品、限购、自选规则、APK或存档表边界。
