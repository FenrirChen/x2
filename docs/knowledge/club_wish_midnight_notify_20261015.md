# 社团祈愿日切通知漏发（2026-10-15）

服务器日期始终按北京时间00:00划分，load_state 会清除 wish_counts/given/help_count。原 watch 使用 refresh_friends 的持久化 friend_day 判定是否需要发送765祈愿次数；若零点后 GetWishingPage、其他社团HTTP操作或变更请求先保存了当天状态，watch 得到 None 并漏发765，客户端继续保留旧次数。该路径可用真实HTTP处理函数复现，不需要改系统日期或活跃存档。

修复：在线通知使用与业务日切独立的进程内 _daily_notify_day，每个在线玩家每天补发一次 FriendData 和 L2C_ClubWishingCount。两条消息实际送达后才确认通知日期；返回0或异常均保留下轮重试机会。后台至多60秒检测，零点边界会直接唤醒。玩家离线后清除通知标记，重连/服务重启按当前真实次数同步，不会把已使用的当天资格重置。

未改变玩法：每天一次，领取后当天不可再次祈愿；未领取的历史捐赠保留，需先领取再重新祈愿相同物品。无服务端日切时间更改，无APK修改。

回归覆盖：23:59/00:00边界，HTTP先保存当天状态的竞态，两种推送失败重试，已用当天次数不误清零，离线跨多日和未领取捐赠保留，日切后领取并重新祈愿。
