# 炼金顾客订单按解锁等级生成（2026-10-14）

## 已确认原因

CollegeService._customer_for 原先固定使用 college_alchemy_catalog.recipes[element]["1"] 作为求购物品，["2"]作为建议物品，与玩家制造配方的recipe_exp完全无关。因此初始订单始终是一级物品，且可能推荐未解锁二级物品。

## 修复规则

顾客偏好元素继续来自原版 CollegeCustomer.Like，保留每日轮换、五位置神格不重复及原有确定性选择。对已选择的偏好元素，在玩家实际解锁配方中选择最高 RecipeLevel。制造与订单共用 AlchemyService.recipe_exp 的经验阈值解锁闭包；非负经验表示解锁，负数占位不算。一级配方作为基础可用配方，背包是否已经生产出物品不影响解锁判断。

建议商品只从该顾客偏好的元素、已经解锁的其它配方中选择，优先最高级，避免建议未解锁商品。没有更高配方时，仍可建议另一个偏好元素的已解锁物品。

订单商品、数量、建议商品随顾客位置保存。反复查询、重登录、期间解锁配方不会偷偷更换已展示订单。成交后清除该位置商品快照及建议状态，下一次592查询按照最新解锁等级生成；顾客身份与其它位置保持不变。拒绝或每日轮换遵循已有刷新规则。历史建议订单只有已解锁且数量符合ProductNum的商品会被继续使用，旧未解锁建议会被修正。

制造产物数量、卖价、经验加价、加价消耗、折扣好感度、事务原子性及请求重放仍使用原有交易实现。本轮没有改动客户端资源或概率，不新增存档表；新位置字段由既有学院状态JSON持久化及完整存档导出/导入。

验证覆盖六元素、1至10级不同解锁组合、负经验占位、经验阈值自动解锁、同一订单跨重登录稳定、成交后升级订单、最高级建议交易、拒绝刷新；回归原有顾客动作、生产、学院状态及PR27–29轮换用例。
