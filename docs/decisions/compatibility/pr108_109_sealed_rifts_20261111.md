保留 goodsId 解析与请求路由、同主题不同阶段 shopId 纠正、活动 family 兼容、失败原因日志及原子支付/限购/回执。

## PR #109

恢复 CollegeQuest E_Chip -> AwardGroup 的神格碎片委托，客户端原生 type=1 显示感叹号，type=2 继续金币交易。两种订单继续使用已解锁配方候选；碎片委托发原表礼包，不同时发金币，不因残留加价开关扣星能；沿用顾客拒绝、扣料、任务事件和同请求回执事务。

委托类型按 PR 的顾客编号确定性分配，约 2/5 为碎片委托。这是兼容分配方式，不声称恢复原服务器概率。

## 封印裂隙成就

原来的十项成就（6007111..6007116、6007145..6007148）rule.kind=passes，绑定成功通关场数，故一场只能增加一次。改为独立 sealed_rifts 计数，不改成功通关统计、跳层规则或奖励阈值。

证据：原版 UnitBase 的 E_LieXi 单位 6541..6550、6562..6572 的 AutoEvent 为 68901..68910、68701..68710。对应 NpcEvent 的 SubEndEvents 为 68912/68712；68911/68711 是开战关门，68921/68721 是传送，不能作为完成数量。

原生 LieXiUnit.DoTrigger（0x18ECF0C）把 NPCEventID 和触发状态发给 NPCEventTrigger；StatsManager.OnNPCEventTrigger（0x1B5DA48）累计 npcTriggerDataAll（+0x28）；FightModule.SetCheckout_NPCNum（0x1444448）把该字典编码成 KeyValuePair_Int32_Int32；结算协议 C2L_CheckoutMainMission 第30字段 npcEventOnNumber 已存在，之前没有用于此成就。

仅成功的当前赛季战斗接受 68712/68912 的数量，排除开启、关门、传送和其他NPC；相同事件在同一包中重复出现取最大值，避免重复列表膨胀；异常数量不计入。结算回执与 season_runs.settled 保证整场只记一次，失败回滚可重试；失败战斗不记进度。没有报告则不虚构数量。

旧版已计入的通关数迁移为已获得的最低裂隙进度，之后只加实际封印数量；已领取成就不重发。没有保留事件明细的历史少计数量不作估算补偿。

反汇编与解码表证据位于 runtime/pr107_109_20261111/，仅本地留存。
