# 单机好友与社团（2026-10-14）

分支：`codex/singleplayer-friends-club`。按用户要求实现独立账号的角色好友和社团，不修改 APK。

## 来源与补正

参考 bluebird0212 的 [好友提案 / issue #33](https://github.com/FenrirChen/x2/issues/33)、[角色好友分支](https://github.com/bluebird0212/x2/tree/feat/friends-ai-players) 和 [社团提案 / PR #37](https://github.com/FenrirChen/x2/pull/37)。保留其角色名册、头像、PBS DTO、GuildWish/GuildChallengeInfo 导出；重新实现持久化和写入。排除提案内额外的“蓝色鸟”作者账号。

修复提案中的账号/NPC 编号冲突、跨账号共享成员、查询自动建团、未邀请角色自动入团、无限重复赠礼/捐献、任意领奖和错误协议字段。角色编号按当前账号生成，存档中仅存内部角色编号；跨账号迁移会自动转换。

## 本轮可验收

- 默认 39 个官方角色好友；名片、支援神格、删好友、添加回来、黑名单和备注。
- 每个好友每日赠收一次友情点，每次 20；赠送每日最多 10 人，收取最多 15 人，总持有上限 5000。
- 17 级后免费创建个人社团；初始仅本人。用户已明确同意复用申请列表邀请好友：同意=入团，拒绝=移除候选，重新打开招募恢复候选。可设置成员职务、踢人、退团、重新创建；本人始终为会长，不允许移交给 NPC。
- 自己发布祈愿时，从已邀请成员中随机选一位立即捐满本次需要的数量。扣金币、数量及解锁级别来自 GuildWish。领取前不提前增加 GotNum，不再吞掉领取入口；可逐条/一键领取，领取后不会再次发货。
- 给成员捐献时精确扣 1 份材料，恰好持有 1 份也可捐献。按 GuildWish.ContributeAward 展开奖励，保留 778000 礼包原权重；每日最多捐 10 次，不可超过目标数量。
- 助力页显示已邀请成员的模拟建设需求。点击助力/一键助力，系统随机挑选一位成员回助本人当前建设队列，提前 60 秒；同一成员对同一建设任务只回助一次。目标成员每天每类需求只能被助力一次，总助力每日上限 50。先下发权威基地状态，再返回 880，界面计时与存储状态一致。60 秒和每日限额属于本次单机兼容规则。
- 好友支援只用于 SectionTable.AssistType=E_Friend 的关卡；服务端生成等级、初始星级、技能和基础属性，拒绝异账号 NPC、错误角色及客户端伪造数值。NPC 等级跟随账号并封顶 60，星级与当前服务端角色解锁原型一致，不改正式角色。
- JSON 状态、请求回执存入已有 activity_state/activity_receipts，纳入完整存档导出/导入。没有私有未导出的社团数据库。

## 当前边界

本轮没有恢复多人聊天、真实玩家关系或跨玩家社团。好友赠收、邀请、祈愿和助力已实现；镜域只接入现有战斗链路的个人次数（初始 3、每日恢复 3、上限 5）、实际成功记录和一次性首通领奖，不伪造 NPC 战绩。社团等级成长、镜域累计伤害/每日积分宝箱及社团商店尚未完整恢复；没有依据的领奖/变更明确返回 13，不返回伪成功。这些附加玩法需另行补齐官方配置和客户端结算证据。

PBS 原客户端存在仅发 `Authorization: Bearer` 的兼容请求，沿用已有邮件接口的活动账号校验；携带真实 token 时严格核对账号。缺少本人字段的成员/建筑查询通过账号专属 NPC 编号定位，绝不使用最后一次登录的玩家。HTTP 工作线程只负责解析和等待，所有 SQLite 社交操作由游戏主循环执行。

## 验证

测试涵盖默认名册、账号隔离、邀请/拒绝/踢人/退团、每日刷新、友情点容量、重复请求与冲突请求、材料精确扣减、捐献/领取、助力回执、HTTP 原生 DTO、token 绑定、完整存档跨账号导入和支援属性校验。另回归存档、战斗、建筑、注册登录与协议编解码。最终玩家界面由用户手动验收。
