## Planned isolated routing

The emulator supports QEMU user-network options. The intended launch boundary
is `restrict=on` plus exactly two guest forwards:

```text
10.0.2.100:80    -> host 127.0.0.1:18080  (bootstrap)
10.0.2.101:29000 -> host 127.0.0.1:29000  (X2 TCP)
```

Inside the disposable guest, only
`ssl-x2zh1login-release.17m3.com -> 10.0.2.100` would be added. With QEMU
`restrict=on`, all other guest-initiated destinations must remain blocked. This
design was not accepted as evidence because the AVD cannot boot yet; no
`runtime/isolation_evidence.json` was created.

## Intended ADB workflow

After a supported accelerator is available:

1. Boot headlessly with the exact restricted network options.
2. Require exactly `emulator-5554` in `device` state.
3. Verify API, release, ABI/ABI list, display and foreground activity by ADB.
4. Install the hash-verified APK but do not launch it.
5. Apply the guest-only hosts override on a legitimately rootable test image.
6. Run `pm clear com.siva.project.x2` and create `x2-clean`.
7. Start local services, generate isolation evidence and run
   `tools/android/android_preflight.py`.
8. Start the app only when `SAFE_TO_RUN=true`.

## Current blocker

```text
FATAL: Your current hypervisor HAXM is no longer supported by the Android Emulator.
Using WHPX is recommended.
```

Resolving this requires an administrator-approved Windows virtualization change.
No APK install, guest hosts modification, network probe, or client launch was
performed.
