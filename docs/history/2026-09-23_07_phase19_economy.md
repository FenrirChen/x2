# Phase 19：经济系统的已确认子集

2026-09-23，进行中。客户端仍为 Revival v0.2 / 官方 2.4（202），未改 APK。
用户选择严格证据方案；未恢复项目集中在根目录 `NEED.md`。

## 实现

- 从现有审计及已知资源路径导出运行时静态目录：5 个 Section、40 个任务、61 条 Gift、58 个 Item；商店静态元数据随目录保存。不会启动时读取/扫描 APK。
- SQLite 奖励流水、普通物品背包、首通记录、任务进度/领取、事件去重、经济战斗 run/结算摘要。首次通关和普通奖励按对应固定 Gift 合并；之后只给普通奖励。旧 Phase 18 练习 run 不补奖。
- 目前准入仍为 2110001、2110801。结算和发奖在同一事务，失败不发奖；同一结算重试返回回执，不重复加资源。换 run 重放旧完整结算拒绝。当前会话的最近一次一小时内 run 才可结算。
- 玩家经验记入 Exp，神格经验记入 HeroExp 资源池，金币/光辉同步 BaseInfo，普通物品同步 ItemAll/ItemUpdate。保留用户 60 级、既有体力和角色级别。自动升级尚未恢复。
- 日/周任务按 IsUse、AcceptLevel 和 RefreshCycle 展示，保存进度与领取状态；登录条件 E_SignInGame 接入认证登录，通关条件接入成功结算（首关不命中目前指定关卡任务）。未接入的业务不增加进度。
- 暂存一个初始任务实例，不猜测日历、不自动重置；登录任务可领取一次。活跃值分别同步 DailyActivity/WeekActivity。普通/异步领奖通路均支持，未完成/错误类型/未知任务拒绝。
- 商店查询、购买、刷新均明确返回未开放（13），不收费。实机证实成功空列表会触发客户端 ShopModule 空引用，因此不能用“成功空店”代替未恢复业务。随机掉落仍为空。不能描述为完整商店或完整掉落已恢复。
